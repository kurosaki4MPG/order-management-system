# STEP75 注文管理業務フロー完成

この手順書は、注文管理システムを業務フローとして説明できる状態にするための確認記録である。

このSTEPでは、`admin` / `operator` / `viewer` の役割差を確認し、注文登録から請求書生成・保存・参照・監視までをひとつの流れとして整理する。

## 目的

- 受注から完了までの流れを説明できるようにする
- 権限ごとにできる操作と見える画面を一致させる
- 注文管理の業務フローが画面、API、AWS のどこで分かれているかを整理する
- 請求書生成、保存、共有、監視までを業務の一部としてまとめる

## 前提

- STEP74 で全機能統合が確認されている
- `admin` / `operator` / `viewer` の Cognito アカウントを使い分けられる
- 注文一覧、詳細、登録、帳票プレビュー、Step Functions、CloudWatch が動作している

## このSTEPで扱う範囲

このSTEPでは、次の 3 つを確認する。

- 権限ごとの画面と API の出し分け
- 注文登録から請求書生成までの業務フロー
- 監視と復旧を含めた業務フローの説明

## 1. 権限ごとの操作範囲を確認する

まず、`admin` / `operator` / `viewer` の違いを確認する。

### 1.1 viewer

確認手順:

1. `viewer` でログインする
2. `注文一覧` に入る
3. `注文詳細` を開く
4. `注文登録` に入ろうとして `forbidden` に遷移することを確認する
5. `注文削除` や `ステータス更新` が見えないことを確認する

確認ポイント:

- 一覧と詳細は見られる
- 登録、更新、削除はできない
- API でも 403 が返る

### 1.2 operator

確認手順:

1. `operator` でログインする
2. `注文登録` を開いて注文を登録する
3. `注文詳細` からステータス更新ができることを確認する
4. 削除操作が見えないことを確認する
5. 削除 API を直接叩くと 403 になることを確認する

確認ポイント:

- 登録と更新はできる
- 削除はできない
- 画面と API の権限が一致する

### 1.3 admin

確認手順:

1. `admin` でログインする
2. `注文登録`、`注文詳細`、`帳票プレビュー` を開く
3. 登録、更新、削除がすべて使えることを確認する
4. 403 にならずに削除できることを確認する

確認ポイント:

- すべての操作が可能
- 業務の最終責任者としての動線がある

## 2. 注文登録から請求書生成までを通す

業務フローの主経路を確認する。

### 確認手順

1. `operator` か `admin` で注文を 1 件登録する
2. 注文一覧に反映されることを確認する
3. 注文詳細で内容が一致していることを確認する
4. `OrderCreated` が EventBridge に送られることを確認する
5. Step Functions の `oms-dev-order-processing-workflow` が開始されることを確認する
6. `prepare` / `finalize` / `invoice` が順に進むことを確認する
7. 請求書が S3 に保存されることを確認する
8. 署名付き URL で一時参照できることを確認する

### 確認ポイント

- 注文登録が後続処理の起点になっている
- 請求書生成が業務フローの一部としてつながっている
- 保存と参照が同じ注文 ID に紐づいている

## 3. 画面と API の役割を説明する

このSTEPでは、画面だけでなく API と AWS の責務も説明できるようにする。

### 役割の整理

- Next.js 画面
  - 操作導線と表示を担う
- API Gateway / Lambda
  - 認証、認可、入力検証、業務処理を担う
- DynamoDB
  - 注文の永続化を担う
- EventBridge / Step Functions / SQS / DLQ
  - 非同期処理と後続フローを担う
- React PDF / S3 / signed URL
  - 帳票生成と保管・配布を担う
- CloudWatch
  - 障害検知と追跡を担う

### 説明できること

- 注文登録後にどのイベントが流れるか
- どの画面がどの API を呼ぶか
- どの AWS サービスがどの役割を持つか
- どこで 401 / 403 / 400 / 500 が返るか

## 4. 業務フロー全体を口頭で説明する

次の順で説明できれば、このSTEPはほぼ完了している。

1. ユーザーは Cognito でログインする
2. 役割に応じて見える画面と操作が変わる
3. 注文を登録すると DynamoDB に保存される
4. `OrderCreated` が EventBridge に流れる
5. Step Functions が注文処理ワークフローを開始する
6. 請求書が生成され、S3 に保存される
7. 署名付き URL で期限付き参照ができる
8. CloudWatch Logs と Alarm で障害を追える
9. 監視結果を見て復旧手順を選べる

## 5. よくある失敗

### viewer でも注文登録できてしまう

確認すること:

- `canCreateOrders` が正しいか
- `forbidden` へのリダイレクトが動いているか
- API 側でも 403 を返しているか

### operator が削除できてしまう

確認すること:

- `canDeleteOrders` が admin 限定になっているか
- 削除ボタンが画面に出ていないか
- 直接 API を叩いたときに 403 になるか

### 業務フローの説明が途中で止まる

確認すること:

- 注文登録から `OrderCreated` までの流れが言えるか
- Step Functions と請求書生成の接続が言えるか
- 保存と署名付き URL の役割が言えるか

## 6. 完了条件

次を満たせば STEP75 は完了である。

- `admin` / `operator` / `viewer` の役割差を説明できる
- 注文登録から請求書生成、保存、参照までを説明できる
- 画面、API、AWS の責務を分けて説明できる
- CloudWatch と障害対応まで含めて業務フローとして説明できる

### 実運用確認メモ

- `viewer` / `operator` / `admin` の権限制御を実機で確認した
- 注文登録から請求書生成、S3 保存、署名付き URL 参照までの流れを実機で確認した
- CloudWatch Logs と Alarm を使って、業務フローと障害追跡の関係を確認した
