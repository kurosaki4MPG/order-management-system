## 2. 目的・適用範囲

### 2.1 目的

- 注文管理システムの画面仕様を、実装可能な粒度で固定する
- 画面遷移、状態、入力検証、エラー表示を明確にする
- コンポーネントテストと E2E テストの観点を揃える

### 2.2 適用範囲

- 注文一覧画面
- ダッシュボード画面
- 注文登録画面
- 注文詳細画面
- PDF プレビュー画面
- ログイン画面
- 権限なし画面

### 2.3 前提条件

- 認証は Cognito セッションを前提とする
- API 契約は別紙 API 設計書に従う
- 画面は Next.js App Router を前提とする

---

## 3. 画面設計方針

- 画面は業務で使いやすいシンプルな構成とする
- エラーは画面上で分かりやすく表示する
- 一覧・詳細・登録・編集は責務を分ける
- PDF プレビューは印刷時の見た目を意識して表示する
- 未ログイン時はログイン画面へ遷移させる
- 権限不足時は権限なし画面を表示する

---

## 4. 共通UI仕様

### 4.1 デザイン方針

- 業務システムとして読みやすいレイアウトとする
- 余白、見出し、テーブル、カードを整理して配置する
- モバイルでは縦積み、PC では 2 カラムや 3 カラムを活用する

### 4.2 共通コンポーネント

- ボタン
- 入力欄
- セレクト
- テーブル
- カード
- バッジ
- トースト
- ローディング表示
- エラー表示

### 4.3 共通状態

- 初期表示
- 読み込み中
- 空データ
- バリデーションエラー
- API エラー
- 権限不足

### 4.4 図表の表現

- 画面モック図は ASCII のワイヤーフレームで表現する
- 処理の流れではなく、画面のレイアウトと箱割りを優先する
- 実画面に近い順序で、ヘッダー、操作列、本文、サイドカードを並べる
- 必要に応じて注釈を併記し、実装上の意図を明示する
- VS Code の Markdown Preview でも崩れにくい形を優先する
- 画像ベースの詳細モックは各画面の SVG を直接参照する

## 6. 画面別詳細

### 6.0 ダッシュボード画面

#### 目的

- 注文処理の全体状況をひと目で確認する

#### 主な要素

- 注文状況サマリーカード
- 最近の注文カード

#### 画面モック図

```text
+-----------------------------------------------------------------------------------------------+
| Sidebar | Header: 注文管理システム / 通知 / ユーザー / ログアウト                             |
|         |-------------------------------------------------------------------------------------|
|         | Title: ダッシュボード                                                               |
|         | 注文処理の状況を確認できます。                                                     |
|         |                                                                                     |
|         | [本日の注文 24] [処理待ち 8] [処理完了 15] [エラー 1]                               |
|         |                                                                                     |
|         | +---------------------------------------------------------------------------------+ |
|         | | 最近の注文                                                                      | |
|         | | 次のステップで注文一覧を実装します。                                            | |
|         | +---------------------------------------------------------------------------------+ |
+-----------------------------------------------------------------------------------------------+
```

#### 操作

- サイドバーから注文一覧、注文登録、帳票プレビューへ遷移する
- 右上のログアウトで認証を解除する

#### 表示方針

- ダッシュボードは詳細操作の入口ではなく、概要確認に限定する
- 重要な件数と状態を先に見せる

### 6.1 注文一覧画面

#### 目的

- 注文を検索し、状態を一覧で確認する

#### 主な要素

- 検索ボックス
- ステータス絞り込み
- 支払方法絞り込み
- 一覧テーブル
- 詳細遷移リンク
- 新規登録ボタン

#### 画面モック図

```text
+-----------------------------------------------------------------------------------------------+
| Sidebar | Header: 注文管理システム / 通知 / ユーザー / ログアウト                             |
|         |-------------------------------------------------------------------------------------|
|         | Title: 注文一覧                                                                     |
|         | 注文状況の確認、検索、絞り込みができます。                                           |
|         |                                                                                     |
|         | [処理待ち] [処理中] [発送済み] [完了] [キャンセル]                                   |
|         |                                                                                     |
|         | +---------------------------------------------------------------------------------+ |
|         | | 検索欄: 注文番号、顧客名、商品名で検索                                         | |
|         | | ステータス: すべてのステータス  支払い方法: すべての支払い方法  [解除]          | |
|         | |---------------------------------------------------------------------------------| |
|         | | 注文番号 | 注文日時 | 顧客 | 商品 | 支払い | ステータス | 合計 | 操作           | |
|         | | ORD-...  | 09/01... | ...  | ...  | ...    | ...       | ...  | [詳細][削除] | |
|         | | ORD-...  | ...      | ...  | ...  | ...    | ...       | ...  | [詳細][削除] | |
|         | +---------------------------------------------------------------------------------+ |
|         |                                                                    5 件 / ページ送り |
+-----------------------------------------------------------------------------------------------+
```

#### 表示項目

| 項目 | 形式 | 説明 |
| --- | --- | --- |
| 注文ID | テキスト | `ORD-...` 形式 |
| 顧客名 | テキスト | 受注者名 |
| ステータス | バッジ | `pending` など |
| 支払方法 | テキスト | `credit-card` など |
| 合計金額 | 金額表示 | 円表示 |
| 更新日時 | 日時 | 日本語形式 |

#### 操作

- 検索条件変更で一覧再取得
- 行クリックで詳細へ遷移
- 新規登録ボタンで登録画面へ遷移

#### エラー表示

- 未認証: ログインへ誘導
- 権限不足: 権限なし画面へ誘導
- API エラー: 一覧下部にエラーメッセージを表示

### 6.2 注文登録画面

#### 目的

- 新規注文を登録する

#### 主な要素

- 顧客名
- メールアドレス
- 送付先住所
- 支払方法
- 明細入力
- 保存ボタン

#### 画面モック図

```text
+-----------------------------------------------------------------------------------------------+
| Sidebar | Header: 注文管理システム / 通知 / ユーザー / ログアウト                             |
|         |-------------------------------------------------------------------------------------|
|         | Title: 注文登録                                                                     |
|         | 顧客情報と注文商品を入力して、新しい注文を登録します。                               |
|         |                                                                                     |
|         | +----------------------------+  +----------------------------+                       |
|         | | 顧客情報カード             |  | 注文商品カード             |                       |
|         | | 顧客名                     |  | 商品名                     |                       |
|         | | メールアドレス             |  | 数量                       |                       |
|         | | 配送先住所                 |  | 単価                       |                       |
|         | | 支払い方法                 |  | [削除]                     |                       |
|         | | 備考                       |  | [商品を追加]               |                       |
|         | +----------------------------+  +----------------------------+                       |
|         |                                                                                     |
|         | 注文合計: ¥0                                                                        |
|         |                                                                                     |
|         |                                                                    [注文を登録]     |
+-----------------------------------------------------------------------------------------------+
```

#### 入力項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 顧客名 | 必須 | 文字列 |
| メールアドレス | 必須 | 形式検証あり |
| 送付先住所 | 必須 | 文字列 |
| 支払方法 | 必須 | 選択式 |
| 明細 | 必須 | 1 件以上 |

#### 操作

- 保存ボタン押下で登録
- 登録成功後は一覧へ遷移または詳細へ遷移
- 入力不備は項目ごとに表示

## 8. 画面状態

### 8.1 ローディング

- スケルトンまたはプレースホルダーを表示する
- ボタンは二重送信を防ぐため無効化する

### 8.2 空データ

- データがない場合は案内文を表示する
- 一覧では「該当なし」を明示する

### 8.3 エラー

- バリデーションエラーは該当項目に表示する
- API エラーは共通文言にする
- 404 は「見つからない」と案内する

---

## 9. 画面テスト観点

- 主要セクションが描画されること
- ボタンと入力欄が表示されること
- 空状態とエラー状態が分かること
- PDF プレビューで 1 ページのみ見えること
- レイアウト崩れの起点となる要素がないこと

---

## 10. 完了条件

- 画面一覧と遷移が整理されている
- 入力項目とエラー表示が定義されている
- PDF プレビューの表示方針が明確である
- テスト観点にそのまま落とし込める

## 11. 統合メモ

- Phase 1 のフロントエンド基盤設計は、`src/app` を前提とする画面構成と共通レイアウト設計として統合した

- Phase 8 の認証・権限画面は、`/login` と `/forbidden` の導線として統合した
- Phase 9 の最終統合は、ダッシュボードから帳票プレビューまでの画面遷移として統合した
