# Phase 5 詳細設計書

## 1. 目的

注文管理システムに帳票出力機能を追加する。
React PDF を使って請求書や出力帳票を生成し、S3 と署名付きURLへつなげる。

対象STEP:
- STEP39 React PDF導入
- STEP40 請求書テンプレート
- STEP41 日本語フォント対応
- STEP42 PDF生成API
- STEP43 S3保存
- STEP44 署名付きURL
- STEP45 Step Functionsとの統合

---

## 2. 全体構成

```text
注文データ
  -> PDFテンプレート
  -> React PDF
  -> Lambda
  -> S3
  -> 署名付きURL
  -> フロントエンド
```

---

## 3. 帳票要件

### 3.1 目的

- 注文内容を人間が読める帳票にする
- 印刷・保存・再配布しやすくする

### 3.2 レイアウト

- ヘッダー
- 受注情報
- 顧客情報
- 明細
- 合計
- 備考

---

## 4. PDF生成設計

### 4.1 入力

- 注文データ
- 顧客情報
- 明細データ
- 生成日時

### 4.2 出力

- PDF バイナリ
- もしくは S3 上のオブジェクト

### 4.3 Lambda の責務

- 入力検証
- テンプレートへの値流し込み
- PDF の生成
- 保存または返却

---

## 5. 日本語フォント設計

- 日本語が文字化けしないことを必須条件とする
- フォントは PDF 生成時に埋め込む
- ブラウザ生成では `public/fonts` の WOFF2 を使う
- サーバー生成では Lambda 実行環境のローカルファイルを使う
- フォントファイルは Lambda 実行環境で参照可能にする

---

## 6. S3 保存設計

### 6.1 保存対象

- 生成済みPDF

### 6.2 キー設計

- `orders/<orderId>/invoice.pdf`
- `orders/<orderId>/invoices/<timestamp>.pdf`

### 6.3 方針

- 再生成を考慮して上書きかバージョン化かを決める
- 必要なら監査目的で履歴保存する

---

## 7. 署名付きURL設計

- 一時アクセス用に発行する
- 有効期限を短くする
- フロントエンドはダウンロード導線として使う

---

## 8. Step Functions 連携

- 注文処理の後続で帳票生成を呼ぶ
- 失敗時はワークフローの失敗として追跡する
- 再実行できる単位で分割する

---

## 9. Phase 5 の完了条件

- PDF を生成できる
- 日本語が正しく出る
- S3 に保存できる
- 署名付きURLで配布できる
- ワークフローから呼べる
